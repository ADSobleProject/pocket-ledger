# 포켓 가계부 (Pocket Ledger)

구글 스프레드시트를 그대로 두고 쓰는 **모바일 가계부 웹앱**입니다.
시트는 데이터베이스, 이 앱은 그 위의 입력·조회 화면입니다.

**▶ 앱 열기: https://adsobleproject.github.io/pocket-ledger/**

- 📱 폰에서 앱처럼 설치 (PWA · 홈 화면 추가)
- 🔒 시트 ID·비밀번호를 코드에 저장하지 않음 — 앱 첫 화면에서 **웹 앱 URL + PIN** 을 입력하면 이 기기에만 저장됩니다
- ✍️ 입력은 `시트1` 마지막 행에 한 줄 추가하는 것뿐, 수식 탭은 건드리지 않습니다
- ✏️ 내역을 탭하면 **수정 · 삭제** — 그 행의 A~H열만 고치고 메일ID(I열)는 보존합니다
- 💍 결혼준비 지출은 따로 모아 생활비 집계에서 제외
- 🧾 **별도지출** — 비고에 `#제외` 가 붙고 `#결혼준비` · `#충전` · `#저축`·`#적금` 이 아닌 지출(연납 자동차보험료 등)을 `결혼/별도` 탭에서 따로 모아 봅니다
- 🧮 **이번 달 실지출** — 홈 히어로 아래에 생활비 + 결혼준비 + 별도지출을 더한 실제로 나간 돈과, 수입에서 뺀 **실제 순현금**(마이너스면 붉게)을 함께 보여 줍니다
- 🏦 **저축 이체 제외** — 청년희망적금 이체처럼 내 계좌로 옮긴 돈(`#저축`·`#적금`)은 쓴 돈이 아니므로 생활비·별도지출·실지출 어디에도 더하지 않고, 홈 실지출 카드에 `저축 이체 ₩500,000` 처럼만 따로 적습니다
- 💰 **현재 잔액** — 홈 맨 위에 마지막 카드 결제 알림의 비고(`잔액 3,891,369원`)에서 읽은 **계좌 잔액과 기준 시각**(예: `11/20 21:47 기준`)
- 🗓 **월별 조회** — 내역 탭에서 `모든 달` 또는 달별(`11월` · `10월` …)로 걸러 봅니다. 데이터에 있는 달만 최신순으로 생기고, 검색어·카테고리·생활비/결혼/별도 필터와 함께 걸립니다

## 1. 백엔드 붙이기 (5분)

1. 가계부 스프레드시트 열기 → **확장 프로그램 → Apps Script**
2. 기본 `Code.gs` 내용을 지우고 [`apps-script/Code.gs`](apps-script/Code.gs) 전체를 붙여넣기
3. 맨 위 `const APP_PIN` 을 원하는 **4자리 숫자**로 수정 (기본 `0000`)
4. 저장 → **배포 → 새 배포**
   - 유형: **웹 앱**
   - 다음 사용자로 실행: **나**
   - 액세스 권한: **모든 사람** ← 이 값이 아니면 폰에서 연결되지 않습니다
5. 나온 **웹 앱 URL**(`…/exec`)을 복사

> 독립 스크립트로 만들었다면 `SPREADSHEET_ID` 에 시트 ID를 넣어 주세요.
> PIN 을 바꾼 뒤에는 **배포 → 배포 관리 → 새 버전** 으로 다시 배포해야 반영됩니다.

## 2. 앱 연결

배포된 GitHub Pages 주소를 폰에서 열고, 첫 화면에 **웹 앱 URL** 과 **PIN** 을 입력합니다.
연결되면 홈 화면에 추가하세요.

- Android Chrome: 메뉴 → **앱 설치** / **홈 화면에 추가**

## 3. API

`doGet` 과 `doPost` 모두 JSON 으로 응답합니다.

**GET** `?pin=1234` → 예산, 월별요약, 결혼준비, 시트1 최근 200건

```json
{
  "ok": true,
  "data": {
    "period": { "month": "2026-11", "daysLeft": 16 },
    "budget": { "period": {...}, "rows": [...], "total": {...} },
    "monthly": [{ "month": "2026-11", "income": 0, "expense": 0, "net": 0, "rate": 0, "count": 0 }],
    "wedding": { "summary": { "spend": 0, "refund": 0, "net": 0, "count": 0 }, "rows": [...] },
    "transactions": [{ "row": 12, "date": "2026-11-15", "time": "12:30", "merchant": "...", "type": "출금", "amount": 12000, "method": "...", "category": "식사", "note": "", "mailId": "..." }]
  }
}
```

**POST** (`Content-Type: text/plain` — CORS preflight 회피용)

```json
{
  "pin": "1234", "action": "append",
  "date": "2026-11-15", "time": "12:30", "merchant": "스타벅스",
  "type": "출금", "amount": 5600, "method": "토스",
  "category": "카페/간식", "note": "", "isWedding": false
}
```

`isWedding: true` 이면 비고에 `#결혼준비 #제외` 가 자동으로 붙고, 메일ID 는 `webapp-<timestamp>` 로 기록됩니다.

**POST · 수정** — `row` 는 GET 으로 받은 거래의 `row`(시트1의 실제 행 번호)입니다.

```json
{
  "pin": "1234", "action": "update", "row": 12,
  "date": "2026-11-15", "time": "12:30", "merchant": "스타벅스 전주점",
  "type": "출금", "amount": 5900, "method": "토스",
  "category": "카페/간식", "note": "", "isWedding": false
}
```

A~H열만 다시 쓰고 I열(메일ID)은 그대로 둡니다. `isWedding: true` 면 비고에 태그를 붙이고,
`false` 면 `#결혼준비` · `#제외` 태그를 지웁니다. 행이 시트 범위를 벗어나거나 비어 있으면
`ROW_OUT_OF_RANGE` / `ROW_EMPTY` 로 거절합니다.

**POST · 삭제**

```json
{ "pin": "1234", "action": "delete", "row": 12, "expectedMerchant": "스타벅스 전주점" }
```

`expectedMerchant` 를 함께 보내면 그 행의 사용처가 일치할 때만 지웁니다.
시트가 그 사이에 바뀌었으면 `ROW_MISMATCH` 로 막고 새로고침을 안내합니다(삭제 사고 방지).

## 5. 홈의 «이번 달 실지출»

홈 히어로는 **생활비(예산 기준)** 만 보여 줍니다. 결혼준비·별도지출은 예산 집계에서 빠지므로
그 숫자만 보면 이번 달에 실제로 나간 돈을 적게 오해하기 쉽습니다. 그래서 히어로 바로 아래에
**«11월 실지출»** 카드를 따로 두고 다음을 한 화면에 보여 줍니다.

| 항목 | 계산 기준 |
|---|---|
| 생활비 | 예산 시트가 계산한 이번 달 생활비 지출 (`budget.total.spent`, `#제외` 는 이미 빠짐) |
| + 결혼준비 | `wedding.rows` 중 해당 월 행 — 입금/환급은 빼고 순액 |
| + 별도지출 | `separate.rows`(없으면 `transactions` 에서 유도) 중 해당 월 행 |
| **= 실지출** | 위 셋의 합 (2026-11 기준 ₩3,470,868) |
| 실제 순현금 | 이번 달 수입(`monthly` 의 `income`) − 실지출. 마이너스면 붉은 경고 톤으로 표시 |

- `#충전` 은 페이 잔액으로, `#저축`·`#적금` 은 내 계좌로 **옮긴 돈**이라 어느 항목에도 더하지 않습니다 (`monthSum` 에서도 건너뛰고, 홈에는 `🏦 저축 이체 ₩500,000` 로만 따로 적습니다).
- 해당 달 거래가 하나도 없으면(새 달 1일 등) `2027년 1월에는 아직 기록이 없어요` 안내로 바뀌고 0원짜리 순현금 카드를 그리지 않습니다.
- 수입을 아직 모르면 (월별요약에 이번 달 행이 없음) 순현금은 `—` 로 두고 마이너스로 단정하지 않습니다.
- 지난달 결혼준비·별도지출 행은 이번 달 실지출에서 빠집니다(월 단위 집계).

## 6. 홈의 «현재 잔액»

KB 결제 알림 메일로 자동 기록한 행은 비고(H열)에 결제 직후 계좌 잔액이 함께 남습니다
(`주차장 이용료 · 잔액 3,891,369원`). 앱은 GET 으로 받은 `transactions` 중
**날짜·시각이 가장 늦은 잔액 행**을 골라 홈 맨 위에 «현재 잔액» 띠로 보여 줍니다 — 백엔드 수정·재배포 없이 프론트엔드만으로 동작합니다.

- 띠에는 금액과 **기준 시각**(`11/20 21:47 기준`), 결제수단(`KB국민`, 가린 카드번호 괄호는 뺌)을 함께 적습니다.
- 잔액은 마지막 결제 **그 시점의 값**이라 그 뒤 입출금은 반영되지 않았을 수 있습니다(카드에 그렇게 밝힘).
- 홈의 «생활비»·«실지출»·«실제 순현금» 은 **이번 달 흐름**이고, «현재 잔액» 은 **지금 통장에 남은 돈**이라 서로 다른 숫자입니다.
- `페이 잔액 +8,100원` 처럼 부호가 붙은 페이 잔액은 계좌 잔액이 아니므로 건너뜁니다.
- 잔액이 적힌 행이 하나도 없으면(예전 내역만 있는 경우) 띠를 그리지 않습니다.

## 7. 내역 탭 월별 조회

내역 탭 맨 위에 달 칩 줄이 생깁니다: `모든 달` · `11월` · `10월` …

- 달 목록은 앱이 받은 거래의 `date` 에서 **동적 생성**해 최신순으로 놓습니다(데이터가 한 달치뿐이면 줄 자체를 그리지 않음).
- 칩 이름은 올해면 `11월`, 다른 해면 `26년 12월` 처럼 연도를 붙입니다. **여러 해가 섞이면**(`26년 12월` · `27년 1월`) 모든 칩에 연도를 붙여 한눈에 구분됩니다.
- 날짜 묶음 헤더·행 날짜도 올해가 아니면 `26년 12월 31일 (목)` · `26/12/31` 처럼 연도를 붙입니다.
- 월 조건은 기존 `txMatches` 에 한 줄로 더해 **검색어 · 카테고리 · 생활비만/전체/결혼만/별도만** 과 동시에 걸립니다.
- 칩을 눌러도 결과 영역(`#listResults`)만 갈아 끼우므로 검색창의 한글 IME 조합은 그대로 유지됩니다(v4 수정 유지).

## 8. 별도지출 표시 방식

`결혼/월별` 탭의 `🧾 별도지출` 세그먼트는 **백엔드 수정 없이** 동작합니다.
앱이 GET 으로 받는 `transactions`(시트1 최근 200건)의 비고를 보고
`#제외` 가 있고 `#결혼준비` · `#충전` · `#저축`·`#적금` 이 아닌 행을 모아 합계·건수를 계산합니다(시트 `별도지출` 탭과 같은 기준).

- `#충전` 은 카카오페이·네이버페이 충전처럼 **쓴 돈이 아니라 페이 잔액으로 옮긴 돈**입니다(예: `카카오페이 충전` 10,000원 ·
  비고 `카카오톡 클라우드 1,900원 결제용 · #충전 #제외`). 시트 `별도지출` 탭과 똑같이 별도지출로도 잡지 않고,
  `생활비만` 에서도 빠져 `전체` 에서만 보입니다. 실제 결제(예: `카카오톡 클라우드` 1,900원)는 그대로 생활비입니다.

- ⚠️ 시트 `별도지출` 탭 수식은 지금 `#충전` 만 빼고 `#저축`·`#적금` 은 빼지 않습니다. 그래서 `시트1` 125행(청년희망적금 500,000원)이 들어간 뒤 시트 탭 누적은 1,140,080원(3건), 앱은 640,080원(1건)으로 다릅니다. 시트도 맞추려면 `별도지출!B2`·`D2`·`A5` 필터에 `NOT(REGEXMATCH(TO_TEXT('시트1'!H2:H),"#저축|#적금"))` 를 더하고, `H2`(건수)에는 빠져 있던 `#충전` 제외도 함께 넣어야 합니다.

- 응답에 `separate: { summary, rows }` 가 있으면 그 값을 우선 사용합니다 — 나중에 `Code.gs` 에
  시트 `별도지출` 탭 읽기를 추가해 재배포하면, 앱은 그대로 누적 전체를 표시합니다.
- 별도지출 · 충전 · 저축 행은 앱에서 **수정할 수 없습니다**. 앱의 수정 저장은 `#결혼준비` · `#제외` 태그를 지우기 때문에
  (`Code.gs` 의 `stripWeddingTags_`), 고치면 생활비로 잡힙니다. 시트1에서 직접 수정하세요.

## 9. 2027년 이후 연도 전환

앱은 연도를 코드에 박아 두지 않았습니다. 해가 바뀌여도 그대로 쓰면 되는 부분과, 시트 한 칸만 손보면 되는 부분은 이렇습니다.

| 항목 | 연도가 바뀌면 |
|---|---|
| 홈 제목·«실지출» 카드 | 백엔드가 주는 `period.month`(예산 `B2`)를 그대로 써서 `2027년 1월 생활비` · `1월 실지출` 로 자동 변경 |
| 예산 탭 `B2` 기준 월 | `=TEXT(TODAY(),"yyyy-mm")` 수식 그대로라 1월 1일에 자동으로 `2027-01` |
| 월별요약 · 정제데이터 | `TEXT(날짜,"yyyy-mm")` 로 만든 글자를 정렬하므로 `2026-12` → `2027-01` 순서가 그대로 맞음 |
| 내역 탭 월 칩 | 데이터에 있는 달을 읽어 만들므로 `27년 1월` 칩이 자동으로 생김 |
| 거래 0건인 새 달 | 히어로는 예산만 보여 주고, 실지출 카드는 `2027년 1월에는 아직 기록이 없어요` 안내로 바뀜 |
| `#저축`·`#적금` | 해가 바뀌어도 계속 생활비·별도지출·실지출에서 빠짐 |

- 홈 숫자는 모두 **예산 시트의 기준 월**을 따릅니다. 기준 월과 오늘 달이 다르면 홈 히어로 아래에
  `예산 시트의 기준 월은 2027년 1월인데 오늘은 2026년 12월이에요` 같은 노란 안내를 띄워 착시를 막습니다.
- 시트 쪽에서 손볼 곳은 `대시보드` 탭 `D5`(월 선택 칸, 지금 `2026-11` 고정)와 `B2` 제목(`2 0 2 6`) 정도입니다.
  `D5` 를 비우면 최신 월을 자동으로 보여 줍니다(`H5` 수식).

## 참고

- `index.html` 의 `app.js?v=11` · `style.css?v=11` 는 GitHub Pages 의 10분 캐시 때문에 붙여 둔 버전입니다.
  app.js/style.css 를 고칠 때 이 번호를 올리고 `sw.js` 의 `CACHE` 이름도 같이 올리면 폰에서 바로 반영됩니다.

- 내역 탭 검색창은 `type="text"` + `#listResults` 부분 갱신입니다. 입력할 때마다 화면 전체를
  다시 그리면 안드로이드 키보드의 한글 조합(IME)이 끊겨 `ㅁㅏㅌㅡ` 처럼 낱자로 들어갑니다.
  검색 input 노드는 그대로 두고 결과 영역만 갈아 끼우세요.

- 결혼/월별 탭 내역 행은 날짜 묶음이 없어 각 행 메타가 `11/16 · 기타지출 · …` 처럼 날짜로 시작합니다.

- 카테고리는 시트의 표준 13개(식사 · 카페/간식 · 생활/마트 · 온라인쇼핑 · 교통/차량 · 주거/통신 ·
  금융/보험 · 의료/건강 · 뷰티/미용 · 문화/예술 · 기타지출 · 주수입 · 기타수입)를 그대로 사용합니다.
- PIN 은 앱과 Apps Script 양쪽에만 있고, 저장소에는 어떤 값도 들어 있지 않습니다.
  PIN 을 아는 사람은 웹 앱 URL 로 시트에 기록을 추가할 수 있으니 URL·PIN 을 공유하지 마세요.
